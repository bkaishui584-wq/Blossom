# Device Control

## 说明

把一句话变成设备动作。没有设备时如实说没有，不假装接到硬件。

只走两个工具：一个是看清单，一个是执行。动作名必须是登记过的，参数范围由设备声明，
要不要用户确认由设备权限服务决定，这一层不替它们做判断。

## 触发条件

- 开灯
- 关灯
- 灯打开
- 舵机
- 转到多少度
- 设备
- 外设
- esp32
- 传感器读数
- 提示音
- 放个音
- 让设备停下
- 接了什么设备

## 输入

- device：设备名（可选，只有一台连着时可以省略）
- action：已登记的动作名，例如 led.set、servo.set_angle、audio.play（可选，缺了就只报能做什么）
- params：动作参数（可选，例如 {"channel": 0, "on": true}、{"channel": 0, "angle_deg": 90}）

舵机角度用 `angle_deg`，范围由设备的机械结构声明，不要自己按 0-180 猜。
提示音只能点设备上已登记的曲目名（`track_id`），不能给文件路径。

## 步骤

1. 看接了什么设备、能做什么动作 | tool=list_device_actions
2. 执行一个已登记的动作 | tool=run_device_action

## 允许工具

- list_device_actions
- run_device_action

## 输出格式

一句结论，加上设备的真实结果。做不了就说清楚是哪一步不行。

## 验收标准

- 只执行登记过的动作，自己编的动作名一律不认
- 收到设备回 completed 才算做成，发出去没等确认不算
- 设备回 rejected 就是它拒收，把错误码一起说清楚，不要当成"完成了但没结果"
- 设备没连、没这个动作、参数越界、要用户确认时，如实说明
- 模拟设备要标出来是模拟的，不能当成真硬件
- 能力以设备自己报的为准（device.get_capabilities），不要替它假设有什么

## 失败处理

- 没有设备：说明现在没有接入设备，可以先去设备中心用模拟设备试
- 要确认的动作：说明这一步要用户点头，不要绕过去
- 超时：说明设备没有确认，不要自动重发
