- `agent/task.py`：任务状态与结构化任务结果

## 服务与工具

调用链固定为 `Tool → Service → API`，Agent Core 不直接访问外部服务。

| 工具 | 权限 | 说明 |
| --- | --- | --- |
| `get_weather` | READ | 查城市天气，Open-Meteo，无需密钥 |
| `get_news` | READ | 头条或关键词搜索，需要 `DESKPET_NEWS_API_KEY` |
| `list_calendar_events` | READ | 查看本地日程 |
| `add_calendar_event` | LOW | 新建日程，时间写 `2026-10-07 09:00` |
| `list_devices` | READ | 查看已接入设备与状态 |
| `get_device_state` | READ | 查看某个设备的详细状态 |
| `send_device_command` | LOW | 给设备发指令，当前只作用于模拟设备 |

服务失败一律如实返回原因，不编造数据，也不会让桌宠崩溃。结果按 `DESKPET_SERVICE_CACHE_TTL` 缓存，
避免重复请求。新闻密钥通过请求头发送，不写进 URL，也不进入日志。

上面这些只读工具里，**不带参数、自己会写人话**的几个（天气、头条、日程、设备状态）由程序直接执行，
不让模型先决定「要不要调工具」：省一轮调用，没配模型时也能照实回答。

```
你说「今天天气怎么样」
  → 程序直接查天气（缓存命中就不重复请求）
  → 有陪伴模型：把结果交给它，用桌宠的语气说一遍
  → 没模型：用程序写好的话直接说「北京现在 18°C，多云。」
```

需要参数的工具（比如「看某台设备的状态」）仍然交给模型理解你的话再调用；
高风险工具永远不会直连，也不会发给陪伴模型。

## 外部设备

设备操作只能走 `Agent → Tool → DeviceManager → DeviceAdapter`，模型不能直接控制设备。
当前只注册一个模拟设备 `mock-1`，不会驱动任何真实硬件，未连接时执行命令会如实报错。

真实硬件默认被拒绝，需要显式设置 `DESKPET_ALLOW_REAL_DEVICES=1` 才能注册非模拟适配器。
未来 ESP32、机器人、传感器都实现 `DeviceAdapter` 的四个方法接入，Agent Core 无需改动。

## 桌面界面

![界面预览](docs/ui-pet-host.png)

```powershell
python -m app.main          # 启动桌宠（默认）
python -m app.main --check  # 环境自检
python -m app.main --chat   # 终端对话
```

桌宠本体是桌面上的角色，窗口只是角色的透明载体：没有标题栏和边框，不在任务栏占位，背景被色键抠掉，
看起来就是角色站在桌面上。左键点一下桌宠会给个小反应，右键弹出轻量菜单（聊天 / 设置 / 隐藏 / 退出），
按住可以拖动，拖到哪都不会掉出屏幕，多显示器也认。位置记在记忆库的 `pet_position`，下次启动还在原处。

聊天是贴在桌宠旁边的小浮层，默认不出现：菜单里选「聊天」，或桌宠主动说话时才展开；右边放不下就自动
翻到左边。选「隐藏」只留一个小点，点它就能把桌宠叫回来。桌面只显示用户自己的 Live2D 角色，
旧的 Canvas 占位脸已从生产界面移除，情绪变化只改变
表情，未提前开发 Live2D 动画系统。界面通过实现 `AvatarProvider` 接管形象，Agent Core 不感知界面。
设置是独立窗口，按基础、个性化、模型、角色、人格、记忆、技能、语音、主动行为、权限、开发者分区。API Key 只显示是否已设置。

## 液态玻璃外观

- 七套渐变主题：Aurora / Ocean / Sakura / Emerald / Sunset / Lavender / 自定义，日/夜各一套色阶，强调色随主题走。
- 用户背景：设置 → 个性化 → 背景图片，选本机图片（PNG / JPG / WebP / BMP），可缩放；只记路径，不复制原图，换图或删图都不会动你的源文件。
- 日夜开关：胶囊轨道 + 浮起的圆形旋钮，切换时滑动过渡。只改工作台配色和背景，**不碰 Live2D 模型、动作、物理和渲染进程**。
- 背景动效：关 / 低（6 秒）/ 标准（3 秒），窗口最小化时自动停；渲染失败自动退回渐变。
- 文字色阶跟主题分开：每个预设 × 日夜都过 4.5 对比度（`tests/test_p102.py`、`tests/test_p111.py` 盯着）。
- 工作台窗口用原生圆角裁切和 0.98 窗口透明度；不再叠加 Acrylic 覆盖层，避免把文字洗白。卡片内部仍是 Pillow 预渲染模糊图 + 磨砂色块。
- 背景图上限 40 MB，小于 200×200 的图不收；读不出来会说明原因并继续用渐变。

聊天浮层与桌宠本体各管各的，互不绑死，样式收在一处：

| 文件 | 职责 |
| --- | --- |
| `ui/theme.py` | 颜色、字体、字号、间距、按钮状态集中定义，换配色只动这一个文件 |
| `ui/chat_view.py` | 聊天浮层：气泡、输入、发送、状态与常用操作 |
| `ui/settings_view.py` | 设置中心：十一个标签页，普通设置与开发者面板分开 |
| `ui/glass.py` | 液态玻璃背景：渐变 / 用户图片的渲染与缓存 |
| `ui/daynight.py` | 日夜切换开关（胶囊轨道 + 浮起旋钮） |
| `ui/desktop.py` | 宿主：接 Agent、牵桌宠、串状态，不自己画样式 |

- 消息分气泡：你说的话靠右，桌宠靠左；主动提醒、任务状态、系统提示、出错、未配置各有样式，报错不再是大段红字塞进正文。
- 任务只在等待确认、等补充信息、完成、失败、已取消这几步单独占一行，普通回复不刷任务状态。
- 聊天浮层的大小和开合状态会记住，退出再打开还是上次的样子。
- 输入框回车即发，长文本自动换行，右侧有滚动条；右下角可以拖着改浮层大小，有最小尺寸兜底。
- 状态写在下沿：思考中、已完成、出错了、已取消。失败和取消都给一个「重试」，点一下把上一句重发。
- 顶栏有「清空」和「设置」。右键消息区：点在一条消息上是「复制这条」「重新生成这条」，
  点在空白处是「复制选中」「复制全部」。复制这条只拿这一条，代码块一起带上；重新生成只对最后一条
  回复开放，旧回复和你说的话不给点，正在生成时也不给点。清空当前对话前一定先问你。
- 模型没配好时只给一条短提示（本地功能照用），不往聊天正文里灌红色错误说明。
- 调试面板只在开发者模式出现，普通界面看不到 Token、路由和堆栈。
- 设置独立成窗口，用标签页分区：基础页管启动、置顶、快捷键、位置与退出；模型页看两个槽位状态；角色页管形象；人格页管性格；记忆页看数据位置和统计；语音页看麦克风与语音包；主动行为页放主动提醒、免打扰、冷却与专注模式；权限页是那组「你说了算」的开关；开发者页在打开开发者模式后显示运行状态。

桌宠本体照旧：透明、可拖动、可点击、可隐藏、位置记得住，情绪仍只走 `Agent → EmotionState → AvatarProvider`。

## 主动陪伴

触发方向固定为：

```
Scheduler tick → 规则门禁 → 命中的事件 → Agent 生成一句自然语言
```

调度器只按规则发事件，不轮询模型。门禁顺序为：用户偏好 → 免打扰时段 → 冷却 → 每日上限 → 程序条件。
模型返回空内容表示不值得打扰，此时保持安静。主动提醒同样会记录 Token 用量。

用户偏好从记忆库读取：`proactive_enabled`（0/1）、`quiet_hours`（如 `23-7`），
以及两个阀门 `proactive.cooldown_seconds` 与 `proactive.max_per_day`。
阀门取「规则值」和「用户值」的较严一边：用户只能让桌宠更安静，不会让它更吵。0 表示不加额外限制。
这两项在设置 →「主动行为」里改，也能用 `DESKPET_PROACTIVE_COOLDOWN` / `DESKPET_PROACTIVE_MAX_PER_DAY` 给默认值。

## 行为与待机

待机与互动全部由程序规则决定，不经过模型，也不会每隔几秒问一次模型：

```
界面定时 / 调度器 -> BehaviorManager -> PetAction -> AvatarProvider
用户点 / 拖 / 靠近 -> BehaviorManager -> PetAction -> AvatarProvider
主动提醒事件      -> BehaviorManager.should_interact() -> 值不值得开口
```

- 待机动作只有眨眼、四处看看、呼吸、轻晃四种，间隔 45-180 秒随机一次，没到点就不动。
- 互动：单击、双击、拖动、右键、鼠标移进 / 移出各对应一个程序写好的反应。长按也已定义动作，等以后需要再接。
- `should_interact()` 综合用户开关、免打扰时段、冷却、用户是否刚说过话、是否全屏（预留给以后接窗口探测），
  给出「可以开口 / 先等等 / 保持安静」三种结论。用户自己设的倒计时提醒带 `local_text`，永远照发，不参与评分。
- 深夜且很久没人理才会睡觉，有人互动立刻醒。活泼性格动得多，安静性格动得少。
- 形象仍走 `AvatarProvider`；`WindowProvider` 是预留给以后接「全屏检测 / 专注模式」的接口，当前用空实现。

## 语音输入与输出

语音只当一种输入方式、一种输出方式，链路固定为：

```
听到：VoiceProvider.listen() -> VoiceInput -> on_text(文字) -> AgentCore.respond()
说出：程序决定要说的话 -> SpeechPipeline.say(文字, 情绪) -> SpeechProvider.speak()
```

- 输入还是空实现（没麦克风），输出已落地（默认关闭，详见「语音输出」一节）；两条管线在没开关时都保持安静，桌宠照常运行。
- 语音包只负责「听到什么」和「怎么发声」；听到的文字走和打字完全相同的回复通道（同一个工作线程，不在界面线程里跑模型）。
- 说出来的内容由程序决定，长度有上限，避免一句提示念个没完；情绪取自 `EmotionState`，模型控制不到发声。
- 报错信息不会被念出来，只有正常回复和主动提醒才会交给语音包。
- Agent Core 里没有任何语音相关代码，所以以后换语音包、接唤醒词都不用改大脑。
- 不做真实麦克风采集、不做唤醒词；语音合成已落地但仍未引入任何音频依赖。
- 开发者模式可以看到语音输入 / 输出状态（输入仍是 `provider: null`；输出开了开关就是真实实现）。

## 工具与权限

模型只能请求工具，执行由程序完成。调用链固定为：

```
模型请求 → ToolRegistry 查表 → PermissionManager 判断 → 参数校验 → 处理器执行 → 审计
```

权限等级与默认策略：

| 等级 | 例子 | 默认行为 |
| --- | --- | --- |
| READ | 天气查询 | 自动允许 |
| LOW | 创建提醒 | 自动允许 |
| MEDIUM | 发送消息 | 需要用户确认 |
| HIGH | 修改文件 | 需要用户确认 |
| CRITICAL | 执行系统命令 | 直接禁止 |

没有确认通道时，需要确认的操作一律拒绝（fail closed）。未知等级按最高风险处理。
模型只会收到与当前输入相关的工具 schema，其余工具连 schema 都不会发送。

## 双模型与任务模式

桌宠的模型能力分两层，各自独立配置、互不影响：

| 角色 | 用途 | 在应用里 | 兼容环境变量 |
| --- | --- | --- | --- |
| Companion Model | 日常聊天、人格、记忆、情绪 | 「日常聊天」用途 | `DESKPET_COMPANION_*`（回退 `AGENT_LLM_*`） |
| Task Model | 真正执行任务时使用 | 「复杂任务」用途 | `DESKPET_TASK_*` |

**第一次配置走界面**：设置 → 模型 → 模型与 API 管理。

- 选服务商（OpenAI / DeepSeek / 通义千问 / 自定义兼容接口），地址和模型 ID 会填好默认值，可以改。
- 贴自己的 API Key（输入框默认掩码），勾选用途（日常聊天 / 复杂任务），点「保存并应用」。
- 「测试连接」会向该地址真实发送一次最小请求（可能产生极少量费用），成功才显示可用。
- Key 用 Windows 当前用户的 DPAPI 加密保存在 `data\secrets\`，`models.json` 只记 `secret_id`；
  换 Windows 用户或换电脑都解不开，需要重填。日志、聊天、导出里都不会出现明文 Key。
- 「设为聊天默认 / 设为任务默认」决定新会话用哪套；聊天顶栏的模型菜单只切当前会话，不影响别的会话。
- 旧的 `.env` 配置第一次启动会自动导入成配置项，`.env` 文件本身不改。

下面的环境变量仍然兼容，只在应用里没有配置时作为回退（例如无人值守部署）：

```
DESKPET_COMPANION_BASE_URL=https://api.deepseek.com/v1
DESKPET_COMPANION_API_KEY=你的密钥
DESKPET_COMPANION_MODEL=deepseek-chat
DESKPET_TASK_BASE_URL=https://api.deepseek.com/v1
DESKPET_TASK_API_KEY=你的密钥
DESKPET_TASK_MODEL=deepseek-chat
```

填完用 `python -m app.main --check` 看两个模型是否变成 `connected`，再启动界面聊天。

### 用本地模型（不联网、不要密钥）

装一个 Ollama 并拉一个模型，再把陪伴模型指到本机，就能完全离线聊天。程序不会替你下载模型，
也不安装任何组件，只认你配好的地址（Ollama 对外就是 OpenAI 兼容接口，所以不用改代码）：

```
DESKPET_COMPANION_BASE_URL=http://127.0.0.1:11434/v1
DESKPET_COMPANION_MODEL=qwen2.5:3b
DESKPET_COMPANION_API_KEY=local
```

- 模型名要和 `ollama list` 里的一致；换模型只改这一行。
- 本地模型第一次加载进显存要几十秒，`AGENT_LLM_TIMEOUT` 建议放宽到 120。
- 想让任务模式也离线跑，就把 `DESKPET_TASK_*` 指向同一个地址。
- 装了什么、还差什么，问一句「本地能力」或看能力中心，由 `local_ability_status` 如实报出。
- 不想用了，把上面这几行删掉即可，其它功能不受影响。

启动默认是陪伴模式，不会自动进入任务模式。切换规则：

```
用户输入 → Intent Router（本机规则，不调用模型）
  闲聊 / 记忆 / 查信息 → Companion Model
  需要动手执行 → TASK_PENDING → 用户确认 → TASK → 任务模型 + 工具 + 权限 → 结果
```

- 「分析」不等于「执行」：「告诉我怎么改」只讨论，「直接帮我改」才进任务。
- 「你能帮我改代码吗？」是能力询问，不会自动动手。
- 「帮我写一段程序 / 一段代码」是创作请求，走陪伴，模型直接在对话里给；
  「帮我修改…」这种动到用户自己项目的才进任务。指名要写到某个文件时也算任务。
- 确认前不会调用任务模型；取消后不再执行任何工具。
- 任务模型同样不能绕过 `PermissionManager`，高风险工具照样被拦。
- 任务模型只收到与任务相关的记忆，不带闲聊历史，也不带整个记忆库。
- 任务中途缺信息时，任务模型可以调用 `ask_user` 提问，桌宠挂起任务等你回答，拿到回答后从原上下文接着跑，不会重开任务。
- 任务完成后回到陪伴模式，由陪伴模型转述结构化结果。
- 陪伴模型只拿安全工具（READ / LOW）。要改文件、跑命令的工具连 schema 都不会发给它，
  只在任务模式里出现；任务模式同样要过权限层，高风险照样被拦。
- 陪伴与任务的模型选择集中在 `model/router.py`，换模型、加角色都不用改 Agent Core。

没有模型时桌宠照常启动：可以看状态、读写记忆、报时间和日期、跑调度器。
它不会假装 AI 回复，会明确说明「当前没有连接聊天模型」。

## 本地能力（不用模型）

桌宠先自己答，答不了才用模型。顺序固定：

```
本地能力 → 安全工具 → 陪伴模型 → 任务模型
```

本地能力不调模型、不花 token、不上网，文字由程序写死，只读本机真实状态。

| 能力 | 例子 | 说明 |
| --- | --- | --- |
| 算数 | 算一下 12*8+3 | AST 白名单求值，不执行任意代码 |
| 单位换算 | 100 公里是多少英里 | 长度 / 重量 / 温度，长单位优先匹配 |
| 报时间 | 现在几点 | 读本机时钟 |
| 报日期 | 今天几号 / 星期几 | 读本机时钟 |
| 倒计时提醒 | 3 秒后提醒我喝水 | 交给调度器一次性事件，到点主动出声 |
| 说状态 | 你现在怎么样 | 报本地模式、情绪、模型是否配置 |
| 系统状态 | 电量 / 内存 | ctypes 读系统，读不到就如实说读不到 |
| 念记忆 | 你还记得什么 | 念最近几条长期记忆 |
| 问记忆 | 我喜欢喝什么 | 只答真实记住的；没记住就直说「我还没有记住这个」，不猜 |
| 问人格 | 你是什么性格 | 报自己的名字与性格强度，不调用模型 |
| 念设置 | 主动提醒开了吗 | 报提醒开关和免打扰时段 |
| 能力边界 | 你会什么 | 说清本地能做什么、什么要模型 |

- 本地能力只答自己能确定的事。天气、新闻这类联网信息不会被本地能力假装回答。
- 没有模型时，倒计时提醒照样能出声，用的是程序写好的话术。
- 算数走 AST 白名单，只允许数字和四则运算，指数超过 64 直接拒绝。
- 本地能力出错或拿不到数据时保持沉默，由上层如实说明，绝不编造结果。

## 记忆系统 V2

记忆分九层，都存在同一个 SQLite 库里，退出程序不会清空，重启继续加载：

| 层 | 存什么 | 落在哪 |
| --- | --- | --- |
| 对话历史 | 每一句真实消息，长期可回看 | `messages` 表 |
| 会话摘要 | 旧对话本地提炼的要点与待办 | `summaries` 表 |
| 长期事实 | 用户明说「记住」的事 | `kind = long_term` |
| 项目 | 正在做的项目相关信息 | `kind = project` |
| 用户偏好 | 用户自己的设置与喜好（称呼等） | `preferences` 表 |
| 习惯 | 从真实聊天时间推断的活跃时段，只当推测 | `habit.inferred` 偏好 |
| 重要事件 | 确实发生过的第一次（首次聊天、首次语音……） | `timeline` 表 |
| 关系信息 | 认识多久、聊过多少次、算什么关系 | `relationship` |
| 人格反馈 | 用户喜欢桌宠怎么说话 | `kind = feedback` |

- 每条记忆都记来源：`USER_EXPLICIT`（用户亲口说，1.0）/ `SYSTEM_OBSERVED`（0.8）/ `MODEL_INFERRED`（0.5）。
  只有用户亲口说的才标成已确认；观察和推断带「（观察到）」「（推测）」进上下文，不冒充用户事实。
- 每条记忆还带元数据：创建时间、最近使用时间、重要度、置信度、是否确认、是否被取代、是否锁定。
- 去重：一模一样的一条不会重复写；同层里说法重合才会走取代。
- 冲突：新说的、更可信的说法会取代同类里说法重合的旧记忆；旧记录不删除，只标记被谁取代，历史还在库里。
- 衰减：普通记忆按 30 天半衰期衰减，重要记忆（`importance >= 2`）按 10 年算，等于长期保存。衰减只影响排序，不删数据。
- 容量：总存储有上限（默认 2000，`DESKPET_MEMORY_CAPACITY`），超出就把最旧最不重要的**归档**，不删除；
  归档项不再进检索，但在记忆管理界面里勾上「含已归档」还能看到。锁定的记忆永远不会被归档。
- 检索条数和存储量分开：每轮只取 `DESKPET_MEMORY_LIMIT` 条（默认 12）相关记忆进上下文，绝不把整个记忆库发给模型。
- 摘要：旧对话由本地规则提炼成「要点 / 待办与未解决」，不靠截断充数，也不用模型。历史消息一条不删，仍可回看。
- 隐私：位置、隐私开关、静默、习惯推断、人格设置这些内部偏好不会进上下文，只有用户自己的偏好才会。
- 防幻觉：记忆里没有的，本地能力直接回「我还没有记住这个。」；系统提示也要求模型只依据「已知记忆」，不许猜。

记忆管理在「设置 → 记忆」或右键桌宠的「记忆」里打开：能看数量、按层翻、搜索、编辑、删除、锁定、
确认推断、看来源、导出 JSON、整库备份。删除必须确认；恢复整库前会先验备份文件，再给当前库留一份副本。

## 人格系统 V2

人格只影响「怎么做、怎么说、是否主动」，不能影响「能不能做」。

| 分块 | 存在哪 | 说明 |
| --- | --- | --- |
| Base Persona | `persona/interface.py` | 名字与基础语气，默认「小蝶」 |
| Traits | `persona/traits.py` | 九种性格 + 强度 0-100，强度低于 20 不生效 |
| Rules | `persona/interface.py` | 行为准则，只描述表达方式 |
| Preferences | `persona/interface.py` | 回答简短、不啰嗦 |
| Feedback | `persona/feedback.py` | 用户说过的「喜欢 / 不喜欢 / 以后这样 / 以后不要这样」 |
| Learned Style | 由 Feedback 整理而来 | 真实反馈整理成两句，附加在人格文本里 |

- 可用性格：温柔、理性、活泼、安静、幽默、好奇、认真、独立、傲娇，可自由组合，例如
  `DESKPET_PERSONA_TRAITS='理性:70,温柔:50'`。
- 只有说到「桌宠的说话方式」的句子才算人格反馈，普通喜好（「我喜欢吃火锅」）不会记成反馈。
- 反馈写进记忆库的 `feedback` 层，同时往 `persona_samples` 表留一条样本。
- 性格强度可以在界面里调（右键「人格」或设置里的「人格」页），保存后立刻生效，并存进偏好
  `persona.traits`；下次启动时套回去。界面里的设置优先于 `.env`。
- 反馈可以撤销：撤销只是归档，这条不再进提示词和上下文，行仍留在库里，能在记忆管理里恢复。
- 面板把人格设定、即时情绪、关系状态、行为规则分开显示，不揉成一段提示词。
- 人格训练端口 `PersonalityTrainingInterface` 只管收集样本，**不做任何训练**：
  `status()` 明确返回 `training: False`。用户以后训练好的人格实现 PersonaProvider 接入。
- 安全：人格文本再长也挤不掉末尾的程序安全边界；人格没有任何执行入口，
  也不能让桌宠跳过任务确认或权限判断。

### 酒馆角色卡导入

人格页的「导入角色卡…」认 SillyTavern 的 `.json` 和 `.png` 两种卡（V1 / V2 / V3，
PNG 读的是 `chara` / `ccv3` 文本块）。导入前一定先出预览：名字、作者、字数、
哪些字段没导入，都列清楚，点「导入并生效」才写进去。

| 卡里的字段 | 怎么处理 |
| --- | --- |
| `description` / `personality` / `scenario` / `mes_example` | 转成第二人称的人格文本；`{{char}}` 换成名字，`{{user}}` 换成"用户" |
| `name` | 写进 `persona.name`，空会话问候跟着换 |
| `first_mes` | 只在预览里展示，不导入：桌宠的问候按名字生成 |
| `system_prompt` / `post_history_instructions` | **不导入**：这两个字段是用来替换系统提示词的，导入等于让外来的卡改写安全边界 |
| `alternate_greetings` / `character_book` / `extensions` | 不导入：避免灌进大量设定或执行卡里的脚本 |

- 每节单独设上限（描述 1200、性格 800、场景 600、示例 900 字），总长不超过 4000 字，
  超了会截断并在预览里写明。
- 内置 12 张卡：6 张原创（阿岚 / 砚青 / 白露 / 火火 / 弦月 / 小满）+
  6 位公版人物（福尔摩斯 / 孙悟空 / 爱丽丝 / 诸葛亮 / 李白 / 堂吉诃德）。
  全部按 V2 格式写，走同一条解析路径。
- 导入过的卡会自动存进卡库（`<数据目录>\persona_cards\*.json`），第一次启动时
  内置卡也会放进去；人格页的「角色卡库」下拉框可以预览、应用，打开文件夹能直接
  把 `.json` 丢进去。删掉的卡不会在下次启动时自己长回来。
- 导入会留一条版本记录（`导入角色卡：<名字>`），原来的文本随时能回滚；
  代码在 `persona/cards.py`，不联网、不执行卡里的任何内容。

## 视觉检测事件层

桌宠的「眼睛」分成两层，都不读画面、不认人脸、不训练模型：

| 层 | 文件 | 现在做什么 |
| --- | --- | --- |
| 视觉接口 | `behavior/vision.py` | 只有接口，默认实现永远看不到 |
| 检测事件层 | `behavior/detections.py` | 只收「标签 + 置信度」，出现发一次事件，连续两次看不到才发消失 |

```
检测源 → DetectionWatcher → VISION_DETECTED / VISION_CLEARED → EventBus → 行为 / 实体身体
```

- 只认白名单里的标签（person / cup / cat / dog / book），置信度低于 0.5 的一律丢掉。
- 同一件东西一直在，不会反复发事件；出错或读不到就闭嘴，不猜。
- 当前默认接的是空检测源，所以桌宠看不到任何东西。以后接摄像头或 YOLO 时，只写一个
  `DetectionProvider`（`is_available` + `detect`），Agent Core 无需改动。

## ESP32 适配层

`devices/esp32.py` 是外部硬件的位置，当前只跑模拟传输：

| 部件 | 作用 |
| --- | --- |
| `Esp32Transport` | 串口位置的抽象（open / close / write / read） |
| `LoopbackEsp32Transport` | 内存回环，默认实现，只记录发出去的指令 |
| `validate_command` | 程序校验指令：只允许 servo / led / move / distance |
| `Esp32Adapter` | 实现 `DeviceAdapter`，注册进 DeviceManager 才可能被调用 |

- 舵机角度只收 0-180，速度只收 0-100（超了夹住），方向只认前后左右；其他一律拒绝。
- 要测距离得有设备真的回报读数，没回报就如实留空，不编造数值。
- 真硬件默认被拒绝（`DeviceManager` 拦在注册这一步），要显式打开 `DESKPET_ALLOW_REAL_DEVICES`。
- `send_device_command` 工具改成 ESP32 的指令写法（`{"cmd": "servo", "angle": 90}`），权限仍是 LOW。

## 设备清单

以后你自己准备的外设，写进一份清单就会被认出来：

```
程序启动 → 发现清单 → 逐条校验 → 注册到 DeviceManager → 标了自动连接的连一次
```

清单放在数据目录的 `devices/devices.json`（默认位置，可以用 `DESKPET_DEVICES_DIR` 改）：

```json
{
  "devices": [
    {"name": "小舵机", "kind": "mock", "capabilities": ["servo"], "auto_connect": true},
    {"name": "桌上小车", "kind": "esp32"}
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `name` | 设备名字，必须有，不能重复 |
| `kind` | 设备种类，现在只认 `mock` 与 `esp32`，不写默认 `mock` |
| `capabilities` | 能做什么，纯备查 |
| `auto_connect` | 启动时是否连一次 |
| `options` | 预留给以后的传输参数 |

- 某一条写坏了只会跳过那一条并记进日志，不会让桌宠起不来。
- 清单只能造出模拟设备：真实串口与网络传输还没实现，真实硬件依旧默认被拒。
- 设备很久没有回应会被算作离线（默认 900 秒），只是健康判断，不影响指令。
- 开发者面板多了一行「设备」：数量、名字、已连接、离线、是否允许真实硬件。

## 实体身体

身体只做一件事：把桌宠的状态翻译成设备动作，自己不许碰硬件。

```
情绪 / 行为 / 视觉事件 → PhysicalBody → DeviceManager → DeviceAdapter → 设备
```

| 情绪 | 动作 |
| --- | --- |
| happy | 亮灯 |
| excited | 往前挪一点 |
| curious | 舵机抬眼 |
| sad / neutral / thinking | 舵机在不同的角度 |
| tired / sleepy | 关灯 |

- 小动作（眨眼、呼吸这类待机动画）不打扰设备，只有说话、互动、提醒、睡觉才动。
- 看到什么会有反应：看到人开心，看不到就回到中立。
- 没有连上设备时如实说「现在没有连上实体设备」，绝不假装动了。
- 设备动作全部走 DeviceManager，模型没有直接控制硬件的入口。

## 多宠物

家里可以住不止一只桌宠，每只有自己的名字、人格、形象名和会话：

| 字段 | 说明 |
| --- | --- |
| `id` | 名册里的名字 |
| `name` | 显示名（默认用角色包的显示名） |
| `persona_package` | 用哪个角色包，切换时交给 PersonaProvider |
| `avatar` | 形象名，现在只是记录，等 AvatarProvider 实接 |
| `device` | 绑定哪台设备，留空表示不绑 |

- 名册 = 默认人格一只 + 每个角色包一只。`characters/<名字>/character.json` 放几包就有几只。
- 每只宠物有自己的会话 id（`pet:<名字>`），记忆不串门。
- 「有哪些宠物」「换个宠物 小盐」由程序直接回答和切换，不调用模型。
- 换宠物只换人格和身份，安全边界、权限判断、任务确认一字不改。
- 多智能体指的是陪伴 / 任务两个模型各管一段，加上每只宠物自己的对话与会话，不是一个窗口开很多进程。

## Live2D 接入

形象是三层：接口、接入层、渲染端口。程序不制作模型、不下载模型，也不假装在显示。

```
Agent → EmotionState → AvatarProvider → Live2DProvider → Live2DHost → 独立透明角色窗口
                                     ↘ 透明拖动载体（没模型或没渲染环境时仍可拖动）
```

| 部件 | 文件 | 现在做什么 |
| --- | --- | --- |
| 形象接口 | `avatar/interface.py` | `AvatarProvider` 三个方法，情绪到表情名的映射 |
| 接入层 | `avatar/live2d.py` | 发现模型、校验依赖文件、把情绪和动作对到模型自己的名字上 |
| 渲染宿主 | `avatar/web2d.py` | 父进程侧的遥控器：起停角色窗口、发命令、收状态与鼠标事件 |
| 渲染子进程 | `avatar/web2d_renderer.py` | 透明无边框窗口，自己算命中区域，自己贴住桌宠窗口 |
| 渲染资源 | `resources/live2d/` | 官方 Cubism Core（可再分发）、页面与自写 WebGL 渲染器 |
| 随包角色 | `resources/live2d_models/` | 自带一个角色，第一次启动放进用户数据目录；同名文件夹已经在了就一个字不动 |

渲染方式：主线程归 Tk，pywebview 又必须占主线程，所以角色画面单独跑一个进程。
子进程开一个无边框、置顶的透明窗口，用 `WS_EX_LAYERED` 加颜色键把窗口底色抠掉，
再用官方 Cubism Core 解析 moc3，按图层逐个绘制。透明处不拦鼠标，点在角色身上才算命中。

模型放法（目录可以配，默认在用户数据目录里，程序启动时会把文件夹建好）。
程序自带一个角色（`live2D0`），第一次启动就放进这个目录；想换成自己的模型，
把文件夹放进来，再在配置里写 `DESKPET_LIVE2D_MODEL=<文件夹名>`：

```
live2d/
└── 你的模型名/
    ├── 你的模型名.model3.json     ← 认这个文件
    ├── 你的模型名.2048/texture_00.png
    ├── expressions/…              ← 有就用，没有就跳过
    └── motions/…                  ← 有就用，没有就跳过
```

- 支持 `.model3.json` 与老的 `.model.json`；`FileReferences` 里声明的 Moc、贴图、表情、动作、物理、姿态，都会检查文件在不在。
- 缺文件不假装加载成功：设置页「角色」页签列出缺哪些文件，加载失败也如实说原因。
- 情绪先落到逻辑动作（`happy` → Happy）：角色包的 `actions` 为它配了资源就按角色包播；没配才退回默认表情名映射（`happy` → `smile`），再按模型自己声明的名字去对，对不上就跳过并记一条。
- 动作同理：`nod`、`jump`、`wave` 这类动作名先落到逻辑动作，再走角色包的动作表；角色包没配就退回默认动作组（`TapBody` / `Idle`），模型里没有这组就不播。
- 绘制顺序按 Cubism 官方语义排序：`renderOrders[i]` 是「第 i 个元素画在第几个槽位」，按槽位升序画。这条有测试盯着。
- 设置页「角色」页签可以重新加载、卸载、显示隐藏、调大小；缩放记进偏好，重启照旧。
- 桌宠拖动、隐藏、换位置时角色窗口跟着走；拖角色本身也会带动桌宠。
- 想指定用哪个模型就设 `DESKPET_LIVE2D_MODEL='模型名'`；不想要画面就设 `DESKPET_LIVE2D_RENDER=0`。
- 三份配置文件谁说了算：打包目录里那份只是模板，用户数据目录（`%LOCALAPPDATA%\DeskPet\.env`）覆盖模板，
  操作系统真正设过的环境变量优先级最高。之前模板里的空值会把用户的选择顶掉，模型选到不带动的那一份，
  看起来就是「角色不动」，现在按优先级取值。

- 模型没放、依赖缺失、渲染器没装、pywebview 没装，桌宠照样启动，只保留透明拖动区域，不会报错也不会白屏。

模型本身还缺的东西需要你在 Cubism Editor 里补，程序不代做：

| 想要的效果 | 需要你补什么 |
| --- | --- |
| 眨眼 | `model3.json` 的 `Groups` 里加 `EyeBlink`，指向 `ParamEyeLOpen` / `ParamEyeROpen` |
| 口型 | 同上加 `LipSync`，指向嘴巴开合参数 |
| 表情切换 | `expressions/*.exp.json`，并在 `FileReferences.Expressions` 登记 |
| 动作播放 | `motions/*.motion3.json`，并在 `FileReferences.Motions` 里登记动作组 |
| 头发摆动 | `模型.physics3.json`，并在 `FileReferences.Physics` 登记 |
| 多张 2048 贴图 | 导出时选更大的贴图尺寸，`Textures` 里会有多条 |

以后往模型目录里加动作、加表情，只要按上面的名字登记就会被认出来，接口不用改：
`set_expression(name)`、`play_motion(group, index)`、`set_emotion(emotion)`、`get_status()`。

### 角色包与动作映射

角色包是「人格 + 形象 + 动作」的清单：`characters/<名字>/character.json`。
清单里只写真实存在的资源，缺哪段就少哪段，加字段之前的老角色包照样能用。

| 字段 | 现在做什么 |
| --- | --- |
| `id` / `name` / `version` | 角色标识、显示名、版本号，只用于展示 |
| `persona` | 人格覆盖，交给 `PersonaProvider` |
| `avatar` | `provider`、`model`（模型入口文件名）、`scale`、`visible` |
| `actions` | 逻辑动作到模型资源的映射 |
| `voice` | 语音包名字，只读，本阶段不接 |

`actions` 两种写法都收，认不出的动作名只报告、不改你的文件：

```json
"actions": {
  "Idle": "Idle",
  "Happy": { "motion": "HappyGroup", "index": 0, "expression": "smile" }
}
```

程序的逻辑动作固定这 14 个：Idle、Blink、Speak、Think、Happy、Sad、Curious、Sleep、Tap、Drag、Greeting、TaskStart、TaskSuccess、TaskFailure。
每个动作有四种状态：可用、角色包没配、模型里没有、还没有模型。角色包没配就沿用默认表情与动作；
角色包配了但模型里没有，就如实记一条，不会拿别的动作冒充成功。

情绪、行为、聊天、任务状态都不直接碰渲染器，统一走
`Agent Core / EmotionState → AvatarManager → AvatarProvider`。
换模型、加动作只改 `character.json` 或补模型文件，Agent Core 不动。

### 头部怎么动

头部的 X / Y / Z 由两路合成，一路跟光标，一路待机轻摆，合成之后再过一层弹簧：

- 光标由宿主进程每一轮轮询都读一次，约 25 次/秒。推给页面的是「以桌宠中心为原点、视场取窗口
  宽度 3 倍」的归一化位置。以前视场就是窗口本身，光标离开窗口一个身位就顶到 ±1，头一直贴着
  极限、光标一跨就跳；现在光标在桌宠附近是连续的小幅变化。
- 视线只有一个来源：宿主推来的全局光标。页面自己也收得到鼠标事件（拖动要用），但不能再拿窗口
  坐标换算一遍喂给视线；两套换算叠在一起，光标一进窗口头就会蹿一下。
- 画面按显示器的节奏出帧，上限 60fps（`FRAME_MS`）。以前固定砍到 30fps，帧间隔会在 30 和 40
  毫秒之间来回，光标匀速划过时反而看着一格一格。
- 待机摆动按 dt 累积相位（一个来回 7.2 秒），左右摆、点头、侧倾三路周期不同，停下来再回来
  接着摆，不会突然跳一格。
- 弹簧（劲度 26、阻尼 10.5）负责收敛，掉帧时拆成小步长积分，所以光标来得稀也连着走。
- 碰撞掩码（决定「点得中哪一块」的那张透明图）最多每 2.5 秒重算一次，且只在姿势真的漂了才做，
  实测一次约 6 毫秒，不影响出帧。
- 鼠标只是靠近时，只轻轻歪一下头（侧倾约 2 度、0.8 秒），不是半秒六度的大动作。
- 身体跟着头转：`ParamBodyAngleX` 取头部偏航的 50%，`ParamBodyAngleZ` 跟着侧倾，左右摆是整体
  在摆，不是只有脑袋在晃。
- 幅度与周期写成 `resources/live2d/pet_page.js` 顶部的常量（`POINTER_YAW`、`POINTER_PITCH`、
  `SWAY_SECONDS`、`SWAY_YAW` 等），要更活泼或更安静，改那一处就够。「减少动态效果」打开时
  摆动为零，眨眼保留。

## 语音输出

语音输出是「接入点 + 现实实现」两层：现在真的会出声，但只出声，不听声音。

```
程序决定要说的话 → SpeechPipeline → SpeechProvider → 系统自带语音 → 音箱
EmotionState ─┘（情绪只作为参数传下去）
```

| 层 | 文件 | 负责什么 |
| --- | --- | --- |
| 输出接口 | `voice/tts.py` | `SpeechProvider`：能不能说、说一句、停下 |
| 现实实现 | `voice/speaker.py` | 在当前进程里调用系统自带语音（SAPI）发声 |
| 通路 | `voice/manager.py` 的 `SpeechPipeline` | 限长、压空白、静默门禁、统计说了几句 |

- 默认关闭。要开就设 `DESKPET_VOICE_OUTPUT=1`，语速 `DESKPET_VOICE_RATE`（-10 到 10），音量 `DESKPET_VOICE_VOLUME`（0 到 100）。
- 只调系统自带语音：不开子进程、不碰命令行、不联网、不加第三方库。文字原样交给语音组件，不做任何命令拼接。
- 朗读是异步的，说完之前就返回，不挡住界面；说下一句前会先停掉上一句。
- 不是 Windows、系统语音组件不可用时，如实说做不到，桌宠照常运行，只是不出声。
- 静默模式期间桌宠不说话，语音也一起安静。
- 情绪仍然只由程序从 `EmotionState` 传进来，模型不能直接控制发声。

## 语音包与托盘

语音配置中心在「设置 → 语音」：麦克风、监听、唤醒词、识别引擎、发声、语音包各占一行，
外加一行「怎么说话」，直说现在能不能用说话输入。没有识别引擎时就写「只能打字」，不假装能听。
能开始 / 停止监听、启用 / 停用唤醒词、试听一句话。停掉监听后管线不再采集，
隐私开关 `privacy.listen` 关着时界面上的「开始监听」会被拒绝，人格怎么设都绕不过去。

语音包放在 `DESKPET_VOICES_DIR`（默认 `data/voices`），一个子目录一个包，包内是 `voicepack.json`：

- 导入只登记元数据（id、名称、版本、引擎、语速、音量），不复制、更不执行包里的任何文件。
- 元数据要过校验：id 不合规、引擎不认识、文件过大、JSON 坏了都会被拒绝，并如实告诉你原因。
- 选中哪个包存在偏好 `voice.pack`，是内部设置，不会进模型上下文。
- 包里的 `rate` / `volume` 会覆盖 `.env` 里的朗读参数。

托盘与快捷键都是可选装饰，装不上就安静降级：

- 托盘图标给「显示 / 隐藏、聊天、设置、退出」四个入口；系统不给托盘就不显示，桌宠照常。
- 托盘有自己的线程，菜单命令一律投递回界面线程再执行，不会隔着线程碰界面控件。
- 全局快捷键默认不占用，设了 `DESKPET_HOTKEY`（例 `ctrl+alt+d`）才注册；注册失败只记日志。
- 开机启动只有你自己在「设置 → 基础」勾选后才写进注册表，不默认开启。
- 置顶默认开着，在「设置 → 基础」关掉后就不会再被强制抬到最前。
- 本地时间 / 日期 / 简单算数 / 招呼都不走模型，没有任何模型也能用。

## 数据、隐私与成长

三件事各归各的文件，都不依赖模型，也不联网。

| 想要的能力 | 文件 | 现在能做什么 |
| --- | --- | --- |
| 记忆备份 / 导入 / 删除 | `memory/backup.py` | 导出成 JSON、导入只补缺不覆盖、整库备份与恢复、按条/按类/全部删除 |
| 隐私中心 / 权限中心 | `security/privacy.py` | 把能不能听、能不能看、能不能主动说话集中到一处，设置里可改 |
| 真实时间线 | `memory/timeline.py` | 只记确实发生过的第一次（首次聊天、首次语音、首次接入……） |
| 习惯模型 | `memory/habit.py` | 从真实聊天时间推断活跃时段，只当推测 |

- 备份只导出用户看得见的数据：长期记忆、偏好、关系、日记。不含内部表结构、审计记录和 token 记录。
- 导入只做合并：只补当前没有的，绝不覆盖或删除已有记忆。
- 删除必须显式确认，否则一律拒绝，程序不会自动删除任何记忆。
- 整库恢复会先把当前库另存一份，再写回备份；恢复之后重启桌宠。
- 时间线只记真实数据：第一条消息就是第一次聊天，第一条反馈记忆就是第一次反馈，不编造天数。
- 习惯样本不够时只说「还看不出习惯」；观察结果先当推测，不直接改变行为。
- 隐私开关默认跟当前行为一致（还没接的麦克风、摄像头、文件、真实硬件默认关）。「能不能主动说话」和设置里的「允许主动提醒」是同一个开关。
- 每只宠物各存一份私有记忆：长期记忆带归属，检索只看「自己的 + 公共的」，不会串门。
  迁移只给 `memories` 加一列，老记忆没有归属，等于公共，升级之后一条都不会丢。

## 未来接入点

- 用户训练的人格：实现 `PersonaProvider` 的三个方法即可接入，Agent Core 无需改动。
- 摄像头 / YOLO：实现 `DetectionProvider` 的 `is_available` 与 `detect` 即可接入。
- 真 ESP32：写一个 `Esp32Transport`（串口或网络）并在 `DeviceManager` 打开真实设备开关即可接入。
- 用户准备的 Live2D：模型放进 `live2d/` 就会被发现；画面本身等一个 `Live2DHost` 渲染端口实现。
- 麦克风 / 语音识别 / 唤醒词：实现 `VoiceProvider`、`SpeechToTextProvider`、`WakeWordProvider` 就能接进来，现在这三条仍是空实现。
- 未来的 ESP32 / 机器人 / 传感器：写一个 `Esp32Transport`（串口或网络）并打开 `DESKPET_ALLOW_REAL_DEVICES`，再把设备写进设备清单即可。
- 未来的全屏 / 专注探测：实现 `behavior.manager.WindowProvider` 的 `is_busy()` 即可，行为层无需改动。

情绪流向固定为 Agent → EmotionState → AvatarProvider。模型不能直接控制形象。

目录名使用 `logkit` 而不是 `logging`，避免顶层包遮蔽 Python 标准库 `logging`。

## 桌面应用

开发时用 `python -m app.main` 启动。想让桌宠变成“双击就能开”的程序，打包一次：

```powershell
python -m pip install pyinstaller
.\build.ps1
```

产物在 `dist\Blossom\`：

```
dist\Blossom\
├── Blossom.exe        双击启动，不需要 Python，也不会弹控制台
├── _internal\         Python 运行时与依赖
├── .env               模型配置（密钥留空，自己填）
└── .env.example       配置模板
```

`build.ps1` 同时会在桌面创建 `Blossom.lnk`，指向这个 EXE，工作目录自动设对；
顺手删掉上一次构建留下的 `DeskPet.lnk`，免得两个快捷方式指向两处。
移动程序时整个 `Blossom` 文件夹一起搬；只复制 EXE 会少依赖。

程序名改成 Blossom，用户数据目录仍然是 `%LOCALAPPDATA%\DeskPet`。这是有意的：
改名字不能让记忆、会话、人格和模型配置跟着换地方，所以 `security/config.py` 里
程序名和目录名分成两个常量，重新打包不会动到已有数据。
快捷方式丢了就再跑一次 `.\build.ps1 -ShortcutOnly`。想把桌宠放进开始菜单，加上 `-StartMenu`：
` .\build.ps1 -StartMenu`，会在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs` 放一份
指向同一个 EXE 的快捷方式。默认不放，跟着你自己的选择走。

数据位置分开管：

- 程序目录：EXE 和 `_internal`，只读即可。
- 用户数据：打包后写到 `%LOCALAPPDATA%\DeskPet\data` 和 `logs`，
  所以重新打包不会删掉你的记忆和设置，装到 Program Files 也能写。
  开发模式下数据仍在项目目录里，位置不变。想自己定位置就设 `DESKPET_ROOT`。
- 同一个数据目录下还有 `characters`（角色包）与 `live2d`（你的 Live2D 模型），
  重新打包都不会碰到，把模型文件夹拖进 `live2d` 就会被认出来。

启动失败不会闪退：界面弹出人话提示，完整 traceback 写进 `logs\startup-error.log`，写盘前先脱敏，密钥不会跟着进日志。
启动卡住也不会干等着：界面起了但桌宠窗口 45 秒还没出现，会写一条日志并弹一句人话；已经报过启动错误就不再重复弹。
桌面上的 `live2d` 目录（打包后是 `%LOCALAPPDATA%\DeskPet\live2d`）里放模型文件夹，从快捷方式启动也会认到你的角色。
界面回调里没接住的异常也不会无声消失：进日志，状态栏给一句人话。
桌宠已经在跑时再点一次快捷方式，不会开出第二个，只会把已有窗口叫到前面。

## Agent V3

Agent 的这一步只做三件事：想清楚、说明白、按程序规矩动手。

- 路由先分层：停 / 取消 / 确认 → 本地能力 → 闲聊、咨询、查信息、任务 → 说不清就先问。
  `帮我分析代码` 是咨询，`帮我修改项目` 才是任务，两者不混。
- 任务有边界：单轮限轮数、工具次数、时间和重试；到顶就停下来问，不无限循环。
  任务记录写进 SQLite，重启后能看到历史与待续任务；待续任务只列出来，绝不自动重跑；喊停就真的停。
- 工具带元数据：只读、可取消、可重试、幂等、超时、执行后校验。只把当前相关的工具 schema 发给模型；
  日程写入这类会产生副作用的一步，写完会回库复核一次，读不到就如实算「未校验」。
- 记忆与上下文 V3：上下文按真实 token 预算裁剪，记忆按相关度取少量，旧对话压成摘要；
  用户改口之后新说法取代旧说法，旧的留档但不再优先。
- 主动陪伴 V2：事件触发 + 冷却、免打扰、每日上限、一轮一条；自主话题只从项目进展、日程、
  最近做的任务里取材，取不到就不开口。
- 人格独立性：性格强度真实进提示词，安全边界永远排在最后，人格改不了权限、确认和隐私规则。
- 长期陪伴：日报、周报、提醒管理、项目跟踪都走本地能力，读不到真实记录就说读不到。
- 诊断：开发者面板能看到本轮意图、路由、模式、工具调用、记忆条数、token 与主动行为为什么被跳过。

## V4：聊天工作台与 Skill 系统

聊天界面按一套统一规范重做：字体、字号、间距、圆角、颜色、按钮状态一致；用户消息与桌宠回复分成
气泡，系统提示、错误提示、普通消息各有样式。输入框支持回车发送、长文本换行、滚动和历史定位；
思考中、处理中、失败、取消、重试都有明确状态；消息可复制，清空当前对话前先确认。模型没配好时
显示空状态与配置入口，不再把大段报错塞进聊天正文。调试信息默认隐藏，只在开发者模式显示；主题、
窗口尺寸、位置和侧栏状态都会记住。设置分成独立分区：模型、角色与 Live2D、人格与关系、记忆、技能、
语音、权限、开发者诊断。

Skill 是一层独立能力，和工具分工明确：Skill 说明「怎么做」，Tool 执行「具体动作」，Agent 决定用哪个
Skill 与 Tool，PermissionManager 决定能不能做，Validator 复核做完的结果。统一注册、加载、校验、路由、
执行与记录由 `SkillRegistry`、`SkillLoader`、`SkillValidator`、`SkillRouter`、`SkillExecutor` 和技能
管理界面负责；说明文件用 `SKILL.md`，参考资料按需加载，既不常驻上下文，也不把所有工具 schema 一次
塞给模型。技能导入只解析说明文件，不执行包里的脚本，技能绕不过权限、确认和审计。

首批技能都在 `skills/library/` 下，带真实执行路径与测试：

| 技能 | 做什么 |
| --- | --- |
| `coding-agent` | 读项目结构、追调用链、提最小改动、跑测试、看差异并总结 |
| `research-agent` | 资料搜索、来源筛选、事实核验、方案对比；没有来源不编引用 |
| `file-knowledge` | 本地文件搜索与文档读取；默认只读，批量改动前先预览 |
| `office-agent` | PDF、DOCX、XLSX、CSV、PPTX、Markdown 的读取与写入；写前检查路径 |
| `study-agent` | 分层提示、概念讲解、数学推导、代码解释与复习计划 |
| `personal-workflow` | 日历、待办、提醒、计时器、专注模式、每日总结 |
| `git-review` | 读 Git 状态与差异、审代码、整理提交说明；提交推送仍要走授权 |
| `system-assistant` | 本机时间、日期、运行状态与本地待办，纯本地读数 |
| `day-brief` 风格的 `daily-brief` | 日期、待办、日程、天气、机器状态拼成一段今日简报，规则拼装，不调模型 |
| `screen-context` | 说出当前前台窗口的应用和标题；屏幕感知默认关着，打开才读，不截图 |
| `voice-assistant` | 如实报语音状态：后端、朗读开关、识别引擎、语音包；只读，不开麦 |
| `local-text-processing` | 清理空白空行、去重复行、统计字数行数；纯规则，可复算 |
| `local-task-recovery` | 列出没做完的任务和卡在第几步；只列不重跑 |
| `local-diagnostics` | 给桌宠做体检：目录能不能写、数据库能不能开、模型配没配、最近有没有报错 |
| `local-backup` | 看备份、建备份、按确认后恢复；恢复前先校验，覆盖前先留副本 |
| `local-abilities` | 报本机装了哪些本地能力组件，说清还差什么才能用本地模型和离线语音 |

## 桌宠本体

- 命中体积按角色真实透明像素生成：点到角色才算点到，透明角落让给桌面。
- 单击、双击、悬停、拖动都会转成事件；角色缺动作或表情时如实说明并降级，不编造播放成功。
- 渲染进程被系统回收或崩掉后会自动重起并恢复显示；重起失败只保留透明拖动区域，不影响聊天。
- 启动慢不再误报启动失败：窗口还没出现但日志仍在更新，就继续等，不弹失败提示。
- 第二次双击快捷方式不会开出第二个桌宠，只会把已有窗口叫到前面。
- 正常关闭会依次收掉渲染进程、Scheduler、EventBus 与 SQLite，不留残余进程。

## V5：本地优先（第一阶段）

目标是没有大模型 API 也能一直用。这一阶段先把地基补齐，天气缓存、授权目录的文件工具、
生命状态机、开发工具白名单和 Skill 接入留在后面的阶段。

本地工具（`tools/local.py`，全部 `requires=none`，断网和没密钥都能用）：

| 工具 | 做什么 |
| --- | --- |
| `local_time` | 时间、日期、星期、时区、开机时长 |
| `system_status` | 电量、内存、开机时长；读不到就说读不到 |
| `timer_start` | 倒计时提醒，到点由桌宠主动开口 |
| `pomodoro` | 专注一段加休息一段，两头都提醒 |
| `todo_add` / `todo_list` / `todo_done` | 本地待办，过期会标出来，完成只改状态不删记录 |

计时器把等待交给 Scheduler，不靠模型轮询；没有桌面程序在跑就直说现在计不了。

能力注册表（`agent/capabilities.py` 的 `LocalCapabilityRegistry`）在启动时列出每个能力依赖什么、
现在能不能用，界面可以直接拿这张表。工具也带上依赖标注：`get_weather`、`get_news` 是
`network`，本地工具是 `none`，`ToolRegistry.catalog()` 一次给全。

权限中心（`tools/permission.py`）在等级之外多了范围授权：拒绝、单次、每次确认、持久四种模式。
持久授权必须带范围，只认具体工具加具体路径或命令，不是一个总开关；单次授权不落盘；
撤销立刻生效；路径里带 `..` 一律拒绝；CRITICAL 等级不会被授权解开。判断结果照旧进审计，
而且执行入口会再查一遍权限，不只是界面上查。

第二到第四阶段补齐了这些：

- 天气与新闻缓存会标明「是不是缓存、放了多久」。取不到新数据但还有旧记录时，给旧记录并说清是
  多少分钟前的；没有旧记录就如实报错，绝不编一个实时值（`services/weather.py`、`services/news.py`）。
- 授权目录的文件工具（`tools/workspace.py`）：默认只在工作区里。用户在能力中心持久授权某个目录后，
  读写、搜索、复制才在那些目录内生效；单次授权和拒绝都不会长期放行；目录里带 `..` 一律拒绝；
  永久删除没有对应工具，`copy_file` 覆盖前必须显式说明。
- 应用启动（`tools/apps.py`）：打开 http/https 网址、用系统默认程序打开文档类文件，以及启动用户在
  `DESKPET_APPS` 里登记过的应用。可执行文件不通过「打开文件」代开；权限等级分别是 MEDIUM / HIGH / HIGH。
- 白名单命令 `run_command`：只认 python / pytest / node / cargo / go / gcc / make 这几类，
  `-c` 直接执行代码被拒，命令里带危险指令被拒，工作目录必须落在授权目录内。`git` 写操作仍然只能走 `git_action`。
- 生命状态（`behavior/life.py`）：待机 / 活跃 / 工作 / 休息 / 睡觉，只能按合法路径转换，由用户说话、
  离开、回来、跑完工具这些事件推进，每次切换都发 `life.state` 事件给界面。
- 待办到点提醒（`scheduler/reminders.py`）：新增待办立刻挂上一次性定时器；重启后把没到期的补挂、
  已经错过的补一句，做完的不再响。提醒仍然由 Scheduler 发事件，不轮询模型。
- 晚间收尾与早间天气（`scheduler/rules.py`）：只用真实数据。没配城市就不装天气规则，取不到天气就保持安静。
- 能力与权限中心（`ui/capability_view.py`）：一张表看清能力依赖、工具权限、技能、持久授权和最近执行，
  可以直接撤销授权、授权目录、暂停主动行为。调试信息仍然默认只给开发者看。
- 审计（`security/audit.py`）可以按类别、对象、结论过滤。

## V7：产品级工作台（阶段 1）

先把聊天窗口从「贴着桌宠的小浮层」改成能长时间待着的工作台，消息区和输入区一并收干净：

- 默认尺寸改成屏幕的 80% × 85%，上限 1280 × 920，下限仍是 300 × 360。窗口别的地方照旧：
  可拖动、可缩放、可最大化、记住尺寸与位置、多显示器回来不乱。
- 存着的尺寸是旧默认值 400 × 520 时按「从没调过」处理，直接给新默认；用户自己量过的尺寸不动。
- 窗口够宽（≥ 720）时输入框至少留三行，窄了自动退回一行；行数仍按内容自动长，最长不超过上限。
- 正文最宽 720：窗口再宽就两侧留白，不铺满一整行。自己说的话另占一栏靠右（460 宽），
  和桌宠的话分得开。
- 气泡底色只包住文字本身。Tk 的标签底色默认会把左右留白一起刷满整条，看不出是气泡；
  现在把留白区颜色交给主题管（`lmargincolor` / `rmargincolor`），短句就是一个小气泡，长句才铺开。
- 代码块底色不再多铺一行空的：换行符放在标签外面，代码块前后也不带多余空行。

### 阶段 2：主题系统与动效开关

- 强调色五档：天蓝 / 薄荷 / 紫罗兰 / 玫瑰 / 琥珀，深浅色各有一版（`ui/theme.py` 的 `ACCENTS`）。
  只换按钮、高亮和系统提示的配色，其余颜色照旧跟深浅色走；切主题不会把强调色丢掉。
  存在偏好 `ui_accent`，重启照旧；认不出的名字就地退回默认，不抛异常。
- 设置里的「基础」页多了强调色一排按钮和一句当前值，点一下当场换色。
- 减少动态效果（偏好 `ui_motion`）：勾上之后角色不再自动摆动、不再呼吸，
  眨眼保留（不然看着像卡住了）。偏好发给渲染子进程（`reduced-motion` 命令 →
  页面 `Pet.setMotion`），渲染进程重起后会补发一次。角色没起来时只是记着，不影响启动。

### 阶段 3：任务中心

聊天顶栏多了一个「任务」按钮，桌宠右键菜单里也有一项。窗口只读数据库，不自己跑任何东西：

- 顶部一句总账：共几条、完成几条、失败几条、取消几条；下面五个筛选：全部 / 进行中 / 已完成 / 失败 / 已取消。
  选「进行中」时已结束的任务不会混进来。
- 左列表出状态、目标、更新时间；右边是详情：目标、状态、目录、会话、重试次数、创建与更新时间、
  错误原因，以及每一步的标题、状态、工具、结果和校验。没有分步计划的任务直接说「这条是一步做完的」。
- 「接着做（放回输入框）」把那条的目标放回聊天输入框，发不发由用户决定，程序不替你发。
- 「取消正在跑的任务」真的去调 Agent 的取消入口。没有在跑的时候如实说「现在没有正在跑的任务」，
  不假装取消成功。

### 阶段 4：记忆恢复与清空

记忆窗口原来只能看、改、删、导出和备份整库，现在补齐了另外两个入口：

- 恢复整库：先验文件（是不是 SQLite、是不是桌宠的库、完整不完整），再把当前库另存一份，
  最后才覆盖。文件不对直接拒绝，用户点取消就一个字节都不动。恢复后提示「重启桌宠后生效」。
- 清空全部：问过一次才动，删的是长期记忆、项目、关系和人格反馈；用户自己设的偏好（含人格习惯）
  不在删除范围里，清完照旧生效。

### 阶段 5：系统助手技能

自带技能多了 `system-assistant`，覆盖「系统助手」这一档：时间、日期、星期、时区、开机时长、
电量、内存和本地待办。它只读本机读数，不联网、不需要模型，工具失败就报失败，不估一个数字。

主程序里本地工具的注册挪到了装 Skill 之前：技能声明了哪些工具、校验时就要能找到那些工具，
否则声明本地工具的技能会被打回。

### 阶段 6：首次使用向导、诊断包与版本

- 第一次打开会有一个说明窗口：数据目录、记忆库和日志的真实路径，权限怎么给，
  为什么可以不配模型，以及隐私边界。看过一次就不再弹；已经有记忆或聊过天的老库直接跳过，
  只记一笔，不打扰。
- 设置里多了「导出诊断包」（基础页和开发者页都有）：一个 zip，里面是脱敏报告
  （版本、Python、系统、路径与配置，密钥只说「已配置 / 未配置」）和日志副本。密钥、口令一律不进包。
- 版本号统一放在 `app/version.py`，设置页和诊断报告都读它。
- 设置窗口从 470 × 470 放大到 620 × 560，标签页字号改用小号：十页的标题以前在窄窗口里会被挤成
  单个字，现在整段都在，页名一眼能读全。

打包与分发的说明见 `docs/distribution.md`。

## V9.1 续：文档解析与离线语音（第十一轮）

这一轮装两样东西，都是用户点名的：MarkItDown 读文档，sherpa-onnx 做离线语音。
数据库没动，`live2d` 目录里的模型、动作、参数一个字节没碰；语音只做不测（用户指定）。

### 文档解析

`adapters/documents.py` 是这一层的入口，`tools/workspace.py` 的 `read_document` 工具按这个顺序取正文：

1. 装了 MarkItDown 且文件不超过 25 MB：交给它读，docx / xlsx / pptx / pdf / html / epub / rtf / ipynb 都认，结果带标题、列表和表格。
2. 读不出来或没装：表格走 openpyxl、PDF 走 pdfminer（都是包里本来就有的小库）。
3. 还读不出来：退回项目自带的朴素解析（掏 Office 的 XML、试着解 PDF 文本流）。

每一档都在返回里说明是哪一档读的（`engine` 字段）。只读本地文件，不联网，不执行文档里的宏或脚本。
装了 MarkItDown 时 `read_document` 会提示「装了能读得更整齐」的说明；报告引擎名，不写假话。
MarkItDown 没装也不影响任何功能，只是容器格式退回自带解析。

表格为什么不用 MarkItDown 官方的路线：它的 xlsx 转换器硬依赖 pandas（约 59 MB），
为一个格式把 pandas 塞进安装包不划算，改用 openpyxl（2 MB）读，表格一样能用。

### 离线语音

`voice/stt.py` 加了 `SherpaSttProvider`，配好模型目录就能用 sherpa-onnx 在本机识别，不用联网、不用密钥。
支持三种模型目录，认不出就按顺序逐个试：

- whisper：目录里有 `encoder*.onnx`、`decoder*.onnx`、`tokens.txt`。
- SenseVoice：目录里有 `model*.onnx`（或 `model.int8.onnx`）、`tokens.txt`。
- Paraformer：目录里有 `model*.onnx`（或 `paraformer*.onnx`）、`tokens.txt`。

配置项：`DESKPET_STT_ENGINE=sherpa_onnx`、`DESKPET_STT_MODEL=<模型目录>`，可选 `DESKPET_STT_KIND`
（默认 `auto`）和 `DESKPET_STT_LANGUAGE`（whisper 用得上）。模型文件程序不下载，用户自备，许可随模型卡。
找不到模型或建不起识别器时，如实报不可用并说明原因，不会假装能听。

### 打包

这两项都进了安装包。上一版打包时，onnxruntime 的训练、调优、格式转换子模块被一并收进来，
顺着把本机的 torch（365 MB）、Django（21.8 MB）、psycopg 和 pypdfium2 也拖进包，包体从 183 MB 涨到 631 MB。
现在 `Blossom.spec` 按前缀跳过这些子模块，并加了一串排除清单，包体回到 183.5 MB。
`--check` 也改成真转一份文档（内存里的 html 与表格），打包漏文件时一眼就能看出来。

V9.1 剩下的两阶段做完。数据库没有新增声明式迁移，`live2d` 目录一个字节没碰，屏幕感知仍然默认关闭。

### 界面语义（屏幕感知第二层）

`behavior/awareness.py` 的 `UiAutomationProvider` 现在真能读——本机装了 pywinauto，读的是应用自己公开的可访问性树，不是像素。两条改动：

### 记忆全文检索（SQLite FTS5）

`memory/fts.py`：给记忆建一张 FTS5 虚表 `memories_fts`（外部内容，直接指向 `memories`，正文不存两份）。

- 分词优先用 trigram：中文没有词边界，unicode61 会把一整句当一个词，等于搜不到；trigram 按三字子串命中，中英文都能用。没有 trigram 就退 unicode61，再不行整层停用。
- 插入、修改、删除各有一个触发器，索引跟着记忆一起变；删掉一条记忆，索引里那条也没了。
- 检索顺序：先用索引按正文和关键词缩范围，再按原有的重要度、可信度、新鲜度打分。被取代、已归档的记忆不参与。
- 索引不可用（精简版 SQLite 没有 FTS5）时整层退回原来的关键词扫描，功能不受影响。
- 这是派生数据，随时可以重建；不写成声明式迁移的原因就是「建不出来不能让启动失败」。建成功会在 `schema_migrations` 里补一条 `(15, memory_fts)`。

「本地能力」页和 `--check` 都会报真实状态：建没建、什么分词、索引里多少条。探测只读打开用户库，不建也不改。

## V9.1 收尾：本地知识库（第十三轮）

V9.1 最后一块缺口补上：把用户自己电脑上的目录读成可检索的片段。全程本地，不联网、不上传、不需要模型。

### 用起来是什么样

1. 打开「文件与知识」页（左侧导航，或聊天输入区的知识库图标）。

### 实现

- `knowledge/index.py`：把正文按空行切成段落，小段并成一片，超长段落带 120 字重叠硬切；位置说明记成「第 N 段」或「第 N-M 段（第 K 节）」，方便回原文。索引是 FTS5 虚表 `doc_chunks_fts`（外部内容指向 `doc_chunks`），优先 trigram 分词，插删改都有触发器同步，建不出来整层退回 LIKE。

- 数据库新增声明式迁移 16：`documents` / `doc_chunks` / `doc_sources` 三张表。旧库升级只加表，不动原有数据。索引建成功会在 `schema_migrations` 里补一条 `(17, knowledge_fts)`。
- 工具：`knowledge_search`（只读，返回片段 + 文件名 + 位置）和 `knowledge_status`（只读，报文档数、片段数、分词方式和目录）。模型只能查已经索引好的内容，扩范围要靠用户在界面上加目录。
- 技能：`knowledge-base`，只声明上面两个只读工具，技能库 16 → 17。

### 边界（界面上也这么写）

- 这是关键词命中，不是向量检索。同一件事换个说法可能搜不到，别把没搜到当成资料里没有。
- 只索引用户明确加进来的目录，不自动扫全盘；不加目录就是空的。
- 单份文件超过 8 MB 不读，单份最多留 20 万字进索引。
- 目录和片段索引都存在用户自己的库里，不上传。

## V11：ESP32 实体设备接入层（第十五轮）

这一轮给桌宠留出第一件真硬件的位置：USB 串口的 ESP32。电脑端把你说的话变成登记过的结构化动作发过去，
等设备自己回话了才算做完。手上没有板子的时候，整条链路用一台模拟设备跑通，界面和测试都靠它。

### 只发出去不算完成

协议带版本号，一行一条 JSON：

发出去：`{"version":1,"message_id":"...","device_id":"esp32-main","command":"servo.set_angle","params":{"channel":0,"angle":90}}`

设备回：`{"version":1,"message_id":"...","device_id":"esp32-main","status":"completed","result":{"angle":90},"error":null}`

状态有七个：accepted、running、completed、failed、cancelled、timeout、device_disconnected。
`send()` 会一直等到同一个 `message_id` 收到收尾状态才返回；版本不对、超长、字段类型不对、对不上号的一律拒绝。
`message_id` 是真随机的，不是自增计数器。

### 动作先登记，模型不能乱发

首批登记五个动作，每个都写清楚要哪个能力、参数类型与范围、要不要用户确认、超时和断连怎么办：

| 动作 | 要的能力 | 主要参数 | 权限 |
| --- | --- | --- | --- |
| `device.get_status` | status | 无 | READ |
| `sensor.read` | sensor | channel | READ |
| `led.set` | led | channel、on | LOW |
| `servo.set_angle` | servo | channel、angle | MEDIUM，需确认 |
| `device.stop` | stop | 无 | LOW |

舵机角度范围必须由设备自己声明（`from_device`），没声明就不让动——不拿 0–180 当默认。
`device.stop` 只在固件真的实现了才有效；没实现就如实说，不假装能急停。

### 设备中心

主工作台左侧多了「设备中心」：接了什么设备、连上没有、走的哪个口、固件版本；支持的动作列表；
连接、断开、切到模拟设备；动作测试面板；传感器读数；最近执行结果和错误；紧急停止；串口日志与诊断。

页面上的每个数字都来自设备回报。没连上就写未连接。界面只提交登记过的动作，放不放行由设备权限服务定。

### 权限

- 动作授权按 设备+动作 一条一条给，例如 `device.action:sim-1:servo.set_angle`，不是一个大开关。
- 第一次连串口要你选设备、确认。
- 高风险动作（舵机这类有行程的）单独确认。
- 老规矩：权限判断在工具真正执行那一层再做一次，界面放行不算数。

### 固件

`firmware/esp32_device/`：自己解析 JSON、动作白名单、独立验参数、回报执行状态、拒绝非法指令、带软件看门狗，
开机先把固件版本和支持能力报出来。引脚、通道数、角度范围、安全停机时间都在 `config.h` 里。
接线和烧写步骤见 `firmware/esp32_device/README.md`。

### 没有模型也能用

没有模型或 API 的时候，设备中心的动作测试面板照样能点，走的是预定义动作。
闲聊式的一句「把舵机转到 30 度」要靠模型来理解，这时会明说需要模型。

### 边界

- 模拟设备这边跑通了：连接、动作、确认、超时、取消、断连、重复消息、队列满、越权路径。
- 真串口的逻辑有测试替身覆盖，但没在真 ESP32 上验证过，固件也没在 Arduino IDE 里编译过。
- 模拟设备每条结果都带 `simulated: True`，技能回答里会注明「这是模拟设备的结果」。
- 没有声明的动作会被拒，比如 `motor.spin`。
- 真机要显式打开 `DESKPET_ALLOW_REAL_DEVICES=1`，并在设备清单里写上端口，才会真去开串口。

## V11：ESP32 实体设备接入（第十六轮）

这一轮把桌宠接上真硬件的位置做出来了：USB 串口的经典 ESP32。电脑端把你说的话变成
登记过的结构化动作发过去，等设备自己回确认才算做完。没有板子的时候，整条链路用一台
模拟设备跑通。

### 先说清楚做到哪一步

- 电脑端这一侧：协议、动作白名单、设备授权、任务队列、事件桥、设备中心、设备技能，都做完并且有测试。
- 设备端这一侧：ESP-IDF v5.4.4 工程写完并且**真编译通过**（`deskpet_esp32.bin`，app 分区还剩 82%）。
- **没有在真机上烧写过。** 舵机、传感器、喇叭一个都没接过，外设驱动默认全是模拟实现，
  只记日志、不动引脚。要接真硬件，先把 `firmware/esp32/main/device_config.h` 里的
  型号、引脚、机械范围填对，再把对应的 `*_KIND` 从 0 改成 1。

### 协议

一条消息一行，UTF-8，换行分帧。三种消息：`command`（电脑发）、`response`（设备回）、
`event`（设备主动说）。另外连接建立时用一次 `auth`。

```
发：{"version":1,"type":"command","message_id":"cmd-000001","device_id":"esp32-main",
     "command":"servo.set_angle","params":{"channel":0,"angle_deg":90}}
回：{"version":1,"type":"response","message_id":"cmd-000001","device_id":"esp32-main",
     "status":"completed","result":{"channel":0,"angle_deg":90},"error":null,"error_code":""}
```

状态有八个：accepted、running、completed、failed、**rejected**、cancelled、timeout、device_disconnected。
`rejected` 是设备明确拒收（不认识这条动作、参数越界、没这个能力），和人话原因一起回来。
错误码是一张共用的表（`bad_param` / `out_of_range` / `unknown_command` / `unsupported` 等），
两端都按这张表说话，不各写各的。

一行最多 1024 字节。超过就整行丢掉，不拿半截报文去执行。同一单重发只回上次那一帧，不重复执行。

### 动作

| 动作 | 参数 | 谁的活 |
| --- | --- | --- |
| `device.get_status` | 无 | 固件版本、能力、范围、灯、舵机上次角度、运行时长 |
| `device.get_capabilities` | 无 | 协议版本、固件版本、能力列表、参数范围 |
| `sensor.read` | channel | `valid` / `value` / `unit` / `measured_at_ms` / `error` |
| `led.set` | channel, on | 开关一路灯 |
| `audio.play` | track_id, 可选 volume | 只放设备上已登记的曲目，不给文件路径 |
| `servo.set_angle` | channel, angle_deg, 可选 speed_deg_s / duration_ms | 范围由机械结构声明 |
| `device.stop` | 无 | 让固件把当前动作收掉 |

舵机角度用 `angle_deg`，范围必须由设备自己声明；没声明就不让动，绝不默认 0-180。
`device.stop` **不是硬件急停**，界面上也照实写着这句。

### 设备中心

### 固件

`firmware/esp32/` 是 ESP-IDF v5.4.4 工程。`firmware/esp32_device/` 是早先那份 Arduino
参考实现，留着对照，已经被取代。

编译时注意一件事：**工程路径不能有中文**，ESP-IDF 的 kconfig 处理不了非 ASCII 路径。
放在 `…\项目\deskpet\firmware\esp32` 下会直接配置失败，得先复制到纯英文路径再编译。
这条实测踩过，README 里写清楚了。

串口上只跑协议：`sdkconfig.defaults` 把 IDF 自带控制台关掉，UART0 完全归应用，
日志不会和 JSON 混在同一行。

### Wi-Fi

`devices/wifi.py` 走 TCP，说的还是同一套协议和同一套动作处理，没有第二份逻辑。
连上先发一帧 `auth`，设备认了才继续。**没有加密**，只适合在你信得过的局域网里用；
状态里会照实写 `encrypted: false`。设备清单里写 `kind: wifi` 加 `host` / `tcp_port` / `token` 就用它。

- 字幕浮窗补齐字体、字号、行距、文字颜色、最近字幕数量、自动滚动与暂停滚动。颜色只使用主题内的天蓝、浅青、粉红和高对比色；浅色主题下对比度不足时会自动退回正文色。
- 「操作」菜单和右键菜单可以复制当前字幕、暂停或继续滚动、隐藏窗口。复制内容跟着当前显示模式走，只显示原文时不会带上译文。
- 设置页新增「测试音源」：用户主动点击后只读约 0.8 秒，显示真实峰值音量，随后立即释放设备。采集中会显示音源音量；没有权限、没有音源或没有读到声音时不伪造读数。
- 在线识别线程数可以在 1 到 8 之间调整，默认 2；数值会随字幕会话保存，并在真正加载模型时使用。
- 字幕翻译可以选择任务模型、陪伴模型或关闭。选择只影响新启动的字幕会话；字幕原文会发送给所选模型，云端地址仍需单独打开「字幕云端翻译」权限。
- 新增 `tests/test_subtitle_stage_e.py`，覆盖最近字幕上限、复制、滚动暂停、字体与颜色校验、深浅主题对比度、翻译引擎切换和短时音源测试。

## 实时字幕（阶段 F）

- 音频设备拔出、读取异常或系统音频回环断开后，字幕会话会立即退出运行状态并释放采集设备；设置页和字幕浮窗不再继续显示“运行中”。
- 在线识别器加载或推理失败后也会结束会话，错误直接显示在字幕状态里，不会一边报错一边继续显示“运行中”。
- 「设置 → 语音 → 实时字幕」新增「重新连接」，按上次真实使用的音源、识别模型、语言和显示方式重新建立会话。权限和模型状态仍会在启动前重新检查。
- 字幕浮窗头部显示当前音源、识别语言和目标语言；没有译文时只显示识别语言。
- 单次字幕会话只在内存里保留最近 400 句；正在翻译的句子会等结果回来再清理。开启字幕历史后，最终字幕仍按原有方式写入本地数据库。
- `tests/test_subtitle.py` 新增读取异常、设备静默断开、内存上限和待翻译句保留测试，并检查浮窗的音源与语言标签。
